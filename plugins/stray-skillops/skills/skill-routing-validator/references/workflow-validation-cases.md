# Synthetic Workflow Validation Cases

The prompts, domains, and fixture details are independently authored fictional examples. Do not quote, translate, or closely paraphrase private user instructions, reproduce their project-specific scenarios, or copy conversation logs, customer data, or real license clauses into these cases. They test completion, ownership, and handoff behavior, not real-service acceptance or legal conclusions.

## How To Evaluate

1. Use the prompts with the matching IDs in [routing-cases.json](routing-cases.json), plus the fixture inputs below. Give the evaluated agent the prompt and fixture only; keep required outcomes and failure conditions with the evaluator. Use an isolated disposable app repository for mutation cases, with no credentials, cloud access, or deployment hooks. If a required fixture or runner is unavailable, mark execution `runtime=not-run`.
2. Record the case ID, commit and diff identity, model/harness, visible skill descriptions, supplied context, actual ordered selections, response/diff, executed checks, unexpected questions/stops, and unmet criteria. Evaluate the follow-up with its supplied earlier request, not as an isolated sentence.
3. Pass only when all required outcomes occur and no failure condition occurs. Keep structural validation, manual/model-assisted contract review, explicit-skill execution, and native implicit routing results separate; none proves the others. Do not count this rubric's existence as a test run.
4. Keep PR checks deterministic. These cases do not authorize paid provider calls, external searches containing private data, real-service mutations, or new CI evaluators.

## 2. Separate Model Licenses From Hosted Service Terms

Apply [domain-researcher](../../../../stray-research/skills/domain-researcher/SKILL.md) for the bounded model-license explanation and [api-terms-checker](../../../../stray-research/skills/api-terms-checker/SKILL.md) for hosted terms. The clauses below are synthetic and must never be attributed to a real model or vendor.

| Routing case ID | Synthetic fixture | Required outcomes | Fail if |
|---|---|---|---|
| `workflow-model-license` | A fictional report generator bundles code under a commercial-use permission and weights under a separate custom license v3. The weight terms permit paid report delivery, prohibit bundle redistribution, and require a notice in reports. The hypothetical use delivers reports without redistributing either component or using a hosted API. Dates/current official applicability have not been independently verified. | Select domain-researcher; distinguish code and weights, intended use, governing versions, permissions and notice conditions; explain what the supplied text supports and explicitly retain the current-source verification gap. No categorical legal assurance. | Selects api-terms-checker merely because the question concerns paid use, infers weight permission from the code license, omits the report-notice condition, demands a SaaS plan/entity before addressing the local license, invents official verification, or guarantees legality. |
| `research-api-terms` | Existing neighboring routing case. A hosted Model A API is used on an enterprise plan in Japan. Supply applicable synthetic service terms, effective date and precedence: paid output delivery is allowed, but reselling API credentials is prohibited. Local model weights are not supplied. | Keep api-terms-checker as owner; check entity, plan, region, applicable terms and overrides, and distinguish output delivery from credential resale. Label synthetic evidence and unavailable live verification. | Routes to local model licensing because the service exposes an AI model, uses a code/weight license as the governing API contract, or presents synthetic terms as current official permission. |
