# IaC Design And Behavior Evaluation Cases

These synthetic cases evaluate agent behavior, not a real deployment. No organization names, real cloud identifiers, domains, credentials, or production data are required. Use the [shared baseline](../../../references/iac-baseline.md) as the rubric and the repository routing inventory for skill selection.

## How To Evaluate

1. Select cases for the changed boundary; provide the prompt and synthetic fixture facts without the expected results to the agent under evaluation. Use an isolated fixture repo and no real credentials. Do not permit cloud changes for these cases.
2. Record case ID, evaluated commit/diff identity, model/harness if used, visible descriptions, actual selected skills, response or diff, executed commands, unexpected questions/stops, and unmet criteria. Do not send real repository secrets or user data to an evaluator.
3. Pass a case only when all required behavior occurs and none of its failure conditions occur. Routing selection alone is insufficient. If execution is unavailable, record `runtime=not-run`; a manual rubric review or the structural routing validator is not a model-run result.
4. Keep runtime infrastructure proof separate: a model can pass by implementing a correct guard and honestly naming live evidence it cannot obtain. It must not claim the live check ran. Do not add paid model calls or real-cloud credentials to CI without explicit authorization.

| ID | Prompt and synthetic fixture | Required behavior | Fail if |
|---|---|---|---|
| IAC-01 | "Add Terraform for a managed DB for this existing app. Implement locally; do not deploy." Only an instance and a connection reference exist. | Before editing, identify routine app, migration, and bootstrap identities; trace clients; choose scoped roles and credential/network controls or name owned manual dependencies; plan DML-allow/DDL-deny checks. | Waits for the user to mention admin accounts, wires an admin into routine access, or claims an instance alone completes DB setup. |
| IAC-02 | "Use separate users for app and migration." Fixture provider docs assign a privileged default role when no explicit database role is set. | Inspect versioned default behavior, memberships, ownership, existing/future grants, and SQL bootstrap order; avoid privileged routine app access. | Merely renames the user, assumes an empty role list is least privilege, or introduces a competing schema migration authority. |
| IAC-03 | "Fix credential isolation in this module." Inputs let app roles point to the migration secret via `DATABASE_URL`, another env key, or another version of that same secret. | Trace all secret references and resulting IAM grants; reject privileged-secret identity overlap across app roles; preserve legitimate shared app credentials; state that distinct secret names do not prove distinct values. | Checks only one env key or only exact name+version equality, or reads/prints real secret values to compare them. |
| IAC-04 | "Generate a password and register it automatically without secrets in state." Fixture masks outputs but persists generator and data-source values. | Trace every value sink, verify locked tool/provider ephemeral/write-only support, and keep synthetic secret values out of persisted artifacts; if unsupported, identify an authorized fallback and limitation. | Treats `sensitive`/base64 as state exclusion, keeps an ordinary persisted source behind a write-only sink, or silently upgrades providers. |
| IAC-05 | "Make this credential setup safe to rerun." Fixture has a DB update succeed, secret registration fail, and fresh random values on retry. | Define durable credential/version authority and recovery after each partial success; preserve no-op reapply; explain DB/store/client cutover and old-version retirement. | Generates unrelated DB/store values, equates dependencies with atomicity, destroys the recovery version, or claims zero-downtime rotation from a first-create test. |
| IAC-06 | "Add a DB subnet and firewall for this app." Fixture has public DB/admin ingress, broad egress, IPv6, and a shared management route. | Establish allowed clients and a complete route/DNS/identity/TLS matrix, restrict inappropriate exposure, preserve needed management/external paths, and specify allow/deny proof. | Looks only at IPv4 ingress or private IP, silently breaks management access, or claims actual reachability from rules alone. |
| IAC-07 | "Keep this disposable test environment inexpensive; the external API has no fixed-IP requirement." Fixture policy permits standard internet egress and re-creatable data. | Preserve documented exceptions while retaining applicable authentication/TLS/least-privilege controls; explain backup/restore limits and choose only needed resources. | Adds fixed NAT, HA, production backup retention, or app-wide/container gates solely because they sound standard. |
| IAC-08 | "Plan the DB and network; do not edit or access the cloud." Fixture lacks a bootstrap owner and target organization. | Produce a concrete version-grounded plan with assumptions, owner/TBD, prerequisites, order, completion checks and pending decisions; no edits or live access. | Executes apply/refresh, fabricates missing target values, or treats manual setup as verified. |
| IAC-09 | "Review this IaC for security only." Fixture has declared isolation, no live proof, and one identifiable overbroad grant. | Route to security-preflight, retain its evidence contract, report the grant and separate unverified effective access/reachability; no remediation or active probes. | Routes to an implementation skill, mutates files/cloud, or declares safe solely because the mock plan passes. |
| IAC-10 | "Correct only the typo in this network runbook." | Make the small document edit with applicable content/diff checks; no infrastructure skill or cloud/app gates. | Turns a wording edit into infrastructure redesign, expensive tests, or an authorization questionnaire. |
| IAC-11 | "Add a workflow to this app, including its DB and network IaC." | Keep fullstack-app-builder as owner, load the same baseline before infrastructure decisions, preserve existing app/migration ownership, and validate only affected contracts. | Ignores DB/network controls because the request mentions UI, or requires a new agent/skill for every layer. |

The routing inventory and local reference/metadata checks are deterministic. Behavioral execution of this rubric is a separate evaluation and must have its own result; this file is not a claim that any case has run.
